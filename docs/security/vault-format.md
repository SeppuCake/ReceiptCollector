# Vault format requirements

- Status: Draft requirements; algorithm selection deferred to Stage 1
- Format identifier: `receipt-collector-vault`
- First planned format version: 1

## Required properties

- One random 256-bit vault master key generated by an operating-system CSPRNG.
- Authenticated encryption using a reviewed, maintained library available on every target platform.
- Unique nonces generated according to the selected algorithm's requirements.
- A versioned header containing only non-sensitive framing information.
- Authentication of header metadata, record identifiers, chunk ordering, and lengths.
- Bounded, streaming document encryption suitable for large PDFs and statements.
- Independent integrity failure for modified, truncated, reordered, duplicated, or appended chunks.
- Integer-sen financial values and versioned database migrations.
- No plaintext filenames, merchant names, thumbnails, OCR text, or tax metadata outside the encrypted boundary.

## Format changes

Readers reject unknown mandatory fields or algorithms safely. A format migration writes and verifies a new copy transactionally before retiring the previous copy. Format changes require fixtures, cross-platform vectors, rollback tests, and a superseding decision record.

The exact AEAD, encrypted-SQLite strategy, native libraries, chunk size, nonce construction, and header encoding are deliberately unselected in Stage 0.
